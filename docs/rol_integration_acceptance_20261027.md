# RoL 系统深化：集成验收清单

基线：`bdca1a0` 的八批实现，加本次集成复审修正。真实游戏验收由维护者操作；请在独立测试存档中进行，尤其是死亡、换主与控制台改经验的步骤。细节和边界命令以 [控制台指南第19–26节](rol_console_test_guide.md) 为准。

## 已有源码证据与待验证边界

| 闭环 | 已核对的入口与消费者 | 游戏中仍需确认 |
|---|---|---|
| 原人物和碎片任务 | 原竞争者与遭遇编号、四件碎片的原物品/任务编号、旧任务恢复决策 | 排队窗口的scope存读档、旧窗与原人物肖像 |
| 同行与专长 | 原学者的经验→现场概率、原护卫的实践→费用、原交涉者的实践→长议→原竞争者重逢；实际/显示各自读取共享数值 | 真实出席判定、技能面板重算、费用与概率提示 |
| 家族知识 | 七类个人资料→house底本→付费刊印→原笔记/图表消费者；金面修复可保存一类底本 | house及个人副本的存读档、菜单行和冷却显示 |
| 委托与继承 | 原老搭档观测→本人考据成长与原图表；死亡档案与约定保留各自原人，不传个人XP | 庭廷归属、死亡回调时机、继承后原人物scope |
| 日志与资源 | 23类记录固定原host与贡献者；书库决策使用自有1100×440 DDS | 名称保存、日志筛选、UI缩放及图片遮罩 |

这些结论来自源码、有限状态模型及静态检查。模型不模拟游戏实际旅行、人物属性重算、视觉排版或存读档；本表不是游戏已通过的声明。

## 最短验收路线

1. **同一护卫的开路价格**：按[第25.1节](rol_console_test_guide.md)准备一个实际出席的护卫，分别在两个副本设为59和60探险经验。邀请条款及首关提示应分别为75和50金币；59经验开路先扣75，再升到69，另一个副本扣50。护卫本人获10探险经验，返程50金币报酬另结。观察日志和保存/读档后原人轨道。不要直接触发首关事件代替真实活动。
2. **原交涉者与原竞争者**：按[第26节](rol_console_test_guide.md)给同一实际交涉者60交涉经验，正式参加远征并等待真实竞争者插曲。选择75威望长议，记录原交涉者和原竞争者姓名；只有一次+5进度、减压和原交涉者10XP。下一次真实远征让原竞争者实际到场，插曲发生时检查原人重逢和共同考据。若没有竞争者插曲，重新进行实际活动，直接触发事件不能补齐原scope。
3. **知识归属与现有消费者**：按[第19.3节](rol_console_test_guide.md)准备一份有效Mars笔记并编目；确认个人副本保留、当前house底本数加一。同家后人消耗或等候原副本失效后花40金币刊印，三年冷却、五年副本，并在真实Mars活动启程消费。另抽查星界观测图和爱琴海航路图各一次，分别进入Sevilla和Naxos的原40金币首关；两类图表不会在普通启程时消耗。
4. **原人委托、修复与转手**：按[第20.1节](rol_console_test_guide.md)让符合条件的原老搭档主持星界球观测，半年后付给原人50金币，核对其10考据XP与主人的十年观测图。按[第23节](rol_console_test_guide.md)让金面修复成果保存一份未收录资料；确认项目先付50金币、保存不另收编目费且不再给个人XP/威望。分别测试原人离廷和原物品换主，失效项目不换人或换物领奖。
5. **旧任务与继承**：按[第19.1节](rol_console_test_guide.md)打开碎片任务，检查恢复不重复收费；同一物品的新任务不能被旧窗口消费。按[第17节](rol_console_test_guide.md)检查原人物约定和已有资料在死亡后向继承人转交：接续付款仍针对原人，个人XP不转移；house底本与个人死亡档案各自保持自己的规则。

每条路线至少在关键窗口前后保存、读档一次。菜单显示、日志姓名、是否能在游戏中保留旧窗口以及 `error.log` 中本次相关报错，均记录实际结果；无法构造的情况标明未测。护卫当前费用提示使用事件 `SCOPE.ScriptValue`，请特别比较59/60经验时的显示数与实际扣费。
