## 三方面逐轮结论

技术：扫描活跃加载目录的命名、注册项、重复定义、on_action追加方式、脚本effect/trigger/value、事件、回调、背景及显式/隐式图标引用；没有活跃原版同路径替换或 `replace_path`。现有五链、成长、同行、用途、碎片、继承和跨链模型继续通过。新增兼容检查对临时故障样本能够拒绝原版GUI替换、全局品质key、缺失effect与缺失event，验证门槛能发现这类回归。没有把静态解析器当CK3引擎。

策划：循环已闭合为发现→远征→完整/部分/失败→复盘与重试；真实同行→履约与老搭档；真品→用途→图表→下一地区；个人死亡→资料/原约定自愿接续。稳定学习路线、金币路线、在场学者和图表有明确门槛，部分失败保留长期成果。原竞争者后续欠缺的恢复入口已补齐。五链仍共享骨架、短链内容重复度较高，免费学习开局对合格角色通常优于付费路线；这些属于既有设计取舍，本轮不增加更多事件来掩盖。

数值：逐条核对概率互补、封顶、主阶段进度、费用、完整/部分收益、经验档位、互斥组与累计组。Rome稳定开局后标准参考72.9%；Naxos及三条两关链的有利标准路线为81%，付费稳定开局的两关链剩一检定为90%。这些乘积不含旅行/竞争者损失。高属性high与supreme都封顶95%，极致多花1150金币主要换凯旋奖励；四件真品加传奇阶位的名义月威望合计93%，还有其他独立BUFF；Naxos每级只有4人，名义整团伤害/坚韧约普通重步兵1.20/1.31倍。保留强传奇定位，列为手测观察项，不无依据削弱全套装备。完整计算见 [数值模型](rol_success_model.md)。

## 静态验证证据

最终入口：

```powershell
python tools/ck3_mcp/rol_stdio_probe.py
git diff --check
```

- 5活动、4碎片、5成长/5同行、10用途、2跨链、7继承记录。
- 129个活跃文本文件的兼容检查，5条生命周期；101个阶段按钮增加点击资格复核。
- 英中各1214键；55项既有自有GFX引用，新增兼容扫描亦检查GUI文本图标与隐式图标。
- 84张DDS、59张canonical资源、11个header变体；本轮未改图片。
- 64二元概率列表、88概率提示键、19高概率分支、111个活动选择。
- 130个文件的BOM与严格UTF-8（含GUI/descriptor）、前缀、五个namespace smoke和diff格式检查。临时故障样本验证缺GUI/descriptor BOM和坏UTF-8均被拒绝。

暂存后另执行 `git diff --cached --check -- . ':(exclude)archive/document_snapshots/**'` 检查交付改动。旧文档快照保留原Markdown换行所需的行尾双空格，不为格式警告改写历史；六个退役GUI/custom loc在Git中均识别为100%内容保留的移动。

“验证通过”只覆盖对应源码、有限状态转换、资源文件头和MCP协议；不证明实际活动/回调时序、装备计算、NPC排序、定时事件保存/读档或渲染。历史开发中的游戏加载记录不能替代本次修改后的运行时验证。

## 手测与剩余问题

[控制台指南](rol_console_test_guide.md) 第16节是本轮优先验收清单，第6节提供带真实host/activity作用域的完整/部分结算命令，第12–15节覆盖已有四阶段循环。

1. 先在RoL关闭、仅RoL、日常模组组合的相同物品上比较武器/礼器品质与类型前缀、详情、悬浮及交互选物；日常组合换加载顺序再抽查。原版holy relic和其他新界面不应被旧GUI覆盖。
2. 一次完整、一次部分、一次未推进/已推进失败；观察约一天阶段收尾、归程、经验、冷却和重复窗口。另测真实失效/死亡与继承，确认旧同行不丢失、不自动换人。
3. 最后一件圣物换主/Naxos承接触发圆环且只发一次；竞争者恢复原NPC并只支付一次；传承取向互斥。
4. 用途180/181天、冷却、存读档、转手、旧编号事件；资料与多个约定跨代传递；装备实际叠加与Naxos战斗表现。

未解决的是上述引擎与模组组合验证、较高终局强度/极致筹备性价比的实玩评估，以及任何尚未观测到的动态错误。没有证据宣称兼容所有模组或所有存档。后续凭具体日志、问题存档和操作顺序定向修复；本轮静态审计目标完成后停止自主扩展。
